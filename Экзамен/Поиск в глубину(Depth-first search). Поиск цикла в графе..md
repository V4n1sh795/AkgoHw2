Поиск в глубину (Depth-First Search, DFS) — это фундаментальный алгоритм обхода графа, который исследует ветви графа как можно глубже, прежде чем возвращаться назад (backtracking). Он идеально подходит для поиска циклов, проверки связности, топологической сортировки и поиска компонент связности.

Поиск цикла с помощью DFS реализуется по-разному для **неориентированных** и **ориентированных** графов. Рассмотрим оба случая.

---

### 1. Поиск цикла в неориентированном графе

В неориентированном графе ребро соединяет две вершины в обоих направлениях. 
**Логика:** При обходе мы запоминаем не только посещенные вершины, но и **родительскую вершину** (откуда мы пришли в текущую). Если мы встречаем соседнюю вершину, которая уже была посещена, и она **не является родителем**, значит, мы нашли обратное ребро, которое замыкает цикл.
#### Алгоритм (Python):
```python
def has_cycle_undirected(graph, num_vertices):
    visited = [False] * num_vertices

    def dfs(v, parent):
        visited[v] = True
        for neighbor in graph[v]:
            if not visited[neighbor]:
                # Рекурсивно идем глубже, текущая вершина становится родителем
                if dfs(neighbor, v):
                    return True
            elif neighbor != parent:
                # Если сосед посещен и это не родитель, найден цикл
                return True
        return False

    # Граф может быть несвязным, поэтому запускаем DFS из каждой непосещенной вершины
    for i in range(num_vertices):
        if not visited[i]:
            if dfs(i, -1): # -1 означает отсутствие родителя для стартовой вершины
                return True
    return False

# Пример использования:
# Граф: 0-1, 1-2, 2-0 (цикл)
graph_undirected = {
    0: [1, 2],
    1: [0, 2],
    2: [1, 0]
}
print("Цикл в неориентированном графе:", has_cycle_undirected(graph_undirected, 3)) # True
```

### 2. Поиск цикла в ориентированном графе

В ориентированном графе ребра имеют направление. Простой проверки на "посещенность" недостаточно, так как в графе без циклов (DAG) в одну вершину можно прийти разными путями, и это не будет циклом.
**Логика:** Нам нужно отслеживать не только факт посещения вершины (`visited`), но и вершины, которые находятся **в текущем стеке рекурсии** (`rec_stack`). Если мы попадаем в вершину, которая уже есть в текущем стеке рекурсии, значит, мы нашли обратное ребро (back-edge), а следовательно, и цикл.
#### Алгоритм (Python):
```python
def has_cycle_directed(graph, num_vertices):
    visited = [False] * num_vertices
    rec_stack = [False] * num_vertices # Отслеживает вершины в текущем пути обхода

    def dfs(v):
        visited[v] = True
        rec_stack[v] = True # Добавляем вершину в текущий путь

        for neighbor in graph[v]:
            if not visited[neighbor]:
                if dfs(neighbor):
                    return True
            elif rec_stack[neighbor]:
                # Если сосед уже в текущем стеке рекурсии, найден цикл
                return True
        
        rec_stack[v] = False # Убираем вершину из пути при возврате (backtracking)
        return False

    # Проверяем все компоненты связности
    for i in range(num_vertices):
        if not visited[i]:
            if dfs(i):
                return True
    return False

# Пример использования:
# Граф: 0 -> 1 -> 2 -> 1 (цикл между 1 и 2)
graph_directed = {
    0: [1],
    1: [2],
    2: [1]
}
print("Цикл в ориентированном графе:", has_cycle_directed(graph_directed, 3)) # True
```

### Сложность алгоритмов

Для обоих случаев (ориентированный и неориентированный граф) сложность одинакова:
* **Временная сложность:** $O(V + E)$, где $V$ — количество вершин, $E$ — количество ребер. Каждая вершина и каждое ребро обрабатываются константное число раз.
* **Пространственная сложность:** $O(V)$ для хранения массивов `visited` и `rec_stack` (или `parent`), а также для стека вызовов рекурсии, глубина которого в худшем случае равна $V$.
### Ключевые отличия в подходах:
| Характеристика | Неориентированный граф | Ориентированный граф |
| :--- | :--- | :--- |
| **Доп. информация** | Нужен только `parent` (родитель) | Нужен `rec_stack` (стек рекурсии) |
| **Условие цикла** | Сосед посещен И сосед $\neq$ родитель | Сосед находится в `rec_stack` |
| **Причина** | Ребро к родителю — это просто обратный ход по тому же ребру, а не цикл | Вершина может быть посещена из другой ветки без образования цикла |
