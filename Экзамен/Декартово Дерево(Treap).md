Структура данных Декартово Дерево(Treap). Основные операции. Оценка времени работы всех операций через глубину дерева(саму глубину оценивать не надо).
![[1781374935.png]]
**Декартово дерево (Treap, от *Tree* + *Heap*)** — это структура данных, которая объединяет свойства бинарного дерева поиска (BST) и кучи (Heap). Каждый узел дерева хранит пару значений: `(ключ, приоритет)`. 
- По **ключам** дерево удовлетворяет свойству бинарного дерева поиска (ключ левого потомка < ключ узла < ключ правого потомка).
- По **приоритетам** дерево удовлетворяет свойству кучи (обычно мин-кучи или макс-кучи: приоритет родителя строго меньше или больше приоритетов его детей). Приоритеты обычно задаются случайным образом при вставке, что обеспечивает балансировку дерева в среднем случае.

Ниже приведены основные операции и оценка их времени работы, выраженная **строго через глубину дерева $h$** (где $h$ — максимальное количество узлов на пути от корня до самого глубокого листа, включая корень и лист).

---

### Основные операции

1. **Поиск (Search)**
   - *Описание*: Поиск узла по заданному ключу. Начинаем с корня и на каждом шаге сравниваем искомый ключ с ключом текущего узла. Если искомый ключ меньше, переходим в левое поддерево, если больше — в правое.
   
2. **Вставка (Insert)**
   - *Описание*: Может быть реализована двумя основными способами:
     - *Через повороты*: Вставляем узел как в обычное BST (в лист), присваиваем ему случайный приоритет, а затем выполняем повороты дерева (влево или вправо), чтобы поднять узел и восстановить свойство кучи.
     - *Через Split и Merge*: Разделяем дерево по ключу вставки на два дерева, создаем новый узел и сливаем три дерева: `Merge(Merge(Left, NewNode), Right)`.

3. **Удаление (Delete)**
   - *Описание*: Также реализуется двумя способами:
     - *Через повороты*: Находим удаляемый узел. Пока у него есть оба потомка, мы выполняем поворот с тем потомком, у которого приоритет "лучше" (соответствует свойству кучи), опуская удаляемый узел вниз, пока он не станет листом или узлом с одним потомком, после чего просто удаляем его.
     - *Через Split и Merge*: Разделяем дерево так, чтобы удаляемый ключ оказался в отдельном дереве из одного узла, а затем сливаем оставшиеся левую и правую части.

4. **Разделение (Split)**
   - *Описание*: Разделяет дерево на два дерева $L$ и $R$ по заданному ключу $X$ так, что все ключи в $L$ $\le X$, а все ключи в $R$ $> X$. Рекурсивно спускаемся по дереву: если ключ текущего узла $\le X$, мы рекурсивно вызываем `Split` для его правого поддерева, а текущий узел и его левое поддерево целиком идут в $L$. Иначе — рекурсивно вызываем для левого поддерева, а узел и правое поддерево идут в $R$.

5. **Слияние (Merge)**
   - *Описание*: Объединяет два дерева $L$ и $R$ в одно, при условии, что **все** ключи в $L$ строго меньше **всех** ключей в $R$. Корнем результирующего дерева становится тот из корней $L$ и $R$, чей приоритет лучше (соответствует свойству кучи). Второе дерево рекурсивно сливается с соответствующим (правым для $L$, левым для $R$) поддеревом выбранного корня.

### Оценка времени работы через глубину дерева $h$
Пусть $h$ — текущая глубина (высота) дерева. Все базовые операции выполняются за время, пропорциональное длине пути от корня вниз.

| Операция | Оценка времени через глубину $h$ | Обоснование |
| :--- | :---: | :--- |
| **Поиск** | $\mathcal{O}(h)$ | На каждом шаге алгоритм спускается ровно на один уровень вниз. Максимальное число шагов равно глубине дерева. |
| **Вставка** | $\mathcal{O}(h)$ | Поиск места вставки занимает $\mathcal{O}(h)$. Последующие повороты (или рекурсивные вызовы Split/Merge) также перемещают узел или обрабатывают поддеревья вдоль пути длиной не более $h$, выполняя $\mathcal{O}(1)$ работы на каждом уровне. |
| **Удаление** | $\mathcal{O}(h)$ | Поиск узла занимает $\mathcal{O}(h)$. Количество поворотов, необходимых для "проталкивания" узла к листу, не превышает его текущей глубины, которая $\le h$. |
| **Разделение (Split)** | $\mathcal{O}(h)$ | На каждом уровне рекурсии выполняется $\mathcal{O}(1)$ операций, и рекурсивный вызов идет только в **одно** из поддеревьев. Глубина рекурсии ограничена глубиной исходного дерева $h$. |
| **Слияние (Merge)** | $\mathcal{O}(h)$ | На каждом шаге рекурсии мы выбираем корень и спускаемся на один уровень вниз ровно в одном из сливаемых деревьев. Общее число шагов не превышает суммы глубин сливаемых деревьев, что ограничено глубиной результирующего дерева $h$. |
| **Поиск $k$-го элемента** * | $\mathcal{O}(h)$ | Требует хранения размера поддеревьев. Спуск вниз с выбором направления на основе размера левого поддерева занимает время, пропорциональное глубине. |
| **Обновление / Запрос на отрезке** * | $\mathcal{O}(h)$ | При использовании ленивой пропагации (операции `push_down` и `push_up`), на каждом уровне пути выполняется $\mathcal{O}(1)$ работы. Путь имеет длину $\le h$. |

*\* Примечание: операции со звездочкой характерны для расширенных версий структуры, например, для Неявного Декартова дерева (Implicit Treap), где ключом является индекс элемента.*
