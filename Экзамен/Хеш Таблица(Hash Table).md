
**Хеш-таблица (Hash Table)** — это структура данных, реализующая интерфейс ассоциативного массива. Она позволяет хранить пары «ключ-значение» и обеспечивает быстрый доступ к данным по ключу с помощью специальной **хеш-функции**, которая преобразует ключ в индекс массива (ячейку или «корзину»).
### 1. Основные операции
В хеш-таблице выделяют три базовые операции. В **среднем случае** (при хорошей хеш-функции и адекватном коэффициенте заполнения) все они выполняются за **$O(1)$**.
1. **Вставка (Insert / Put)**: 
   - Вычисляется хеш ключа: `index = hash(key) % size`.
   - Элемент помещается в вычисленную ячейку. Если ячейка занята, применяется алгоритм разрешения коллизий.
2. **Поиск (Search / Get)**: 
   - Вычисляется хеш ключа для нахождения начальной ячейки.
   - Если ключ совпадает, возвращается значение. Если нет, применяется алгоритм разрешения коллизий для поиска нужного ключа в цепочке или следующих ячейках.
3. **Удаление (Delete / Remove)**: 
   - Ключ находится так же, как при поиске.
   - При **методе цепочек** элемент просто удаляется из списка.
   - При **открытой адресации** ячейка помечается специальным флагом (например, `DELETED` или `tombstone`), чтобы не разорвать цепочку пробирования для других ключей.
### 2. Способы обработки коллизий
**Коллизия** возникает, когда хеш-функция для двух разных ключей возвращает одинаковый индекс: `hash(key1) == hash(key2)`. Существует два основных подхода к решению этой проблемы:
#### А. Метод цепочек (Separate Chaining / Открытая хеш-таблица)
Каждая ячейка массива хранит не один элемент, а указатель на структуру данных (чаще всего связный список, но может быть и сбалансированное дерево, например, в `HashMap` Java при большом количестве коллизий).
- **Плюсы**: Таблица не переполняется, удаление элементов простое, нечувствительность к коэффициенту заполнения > 1.
- **Минусы**: Дополнительные затраты памяти на указатели, ухудшение локальности данных (кэш-промахи при обходе списка).
#### Б. Открытая адресация (Open Addressing / Закрытая хеш-таблица)
Все элементы хранятся непосредственно в массиве хеш-таблицы. При коллизии алгоритм ищет следующую свободную ячейку по определенному правилу (пробированию). Коэффициент заполнения ($\alpha = n / m$) всегда должен быть $< 1$.
1. **Линейное пробирование (Linear Probing)**: 
   - Шаг поиска: $+1$. Формула: $H(k, i) = (H'(k) + i) \mod m$.
   - *Проблема*: Первичная кластеризация (группирование занятых ячеек в длинные блоки, что резко замедляет поиск).
2. **Квадратичное пробирование (Quadratic Probing)**: 
   - Шаг поиска растет квадратично. Формула: $H(k, i) = (H'(k) + c_1 \cdot i + c_2 \cdot i^2) \mod m$.
   - *Плюс*: Уменьшает первичную кластеризацию.
   - *Минус*: Может возникнуть вторичная кластеризация (ключи с одинаковым начальным хешем будут проверять одни и те же ячейки).
3. **Двойное хеширование (Double Hashing)**: 
   - Используется вторая хеш-функция для определения шага пробирования. Формула: $H(k, i) = (H_1(k) + i \cdot H_2(k)) \mod m$.
   - *Плюс*: Лучший метод открытой адресации, практически устраняет кластеризацию.
### 3. Время выполнения одной операции в худшем случае
В **худшем случае** время выполнения любой из основных операций (вставка, поиск, удаление) составляет **$O(n)$**, где $n$ — количество элементов в таблице.

**Почему это происходит:**
1. **Плохая хеш-функция**: Если хеш-функция не обеспечивает равномерное распределение, все $n$ ключей могут попасть в одну и ту же ячейку. 
   - При *методе цепочек* это вырождает структуру в обычный связный список длиной $n$, и поиск по нему занимает $O(n)$.
   - При *открытой адресации* это приводит к полному перебору почти всей таблицы.
2. **Высокий коэффициент заполнения ($\alpha \to 1$)**: В открытой адресации, когда таблица почти заполнена, поиск свободной ячейки для вставки или существующего элемента при удалении требует проверки большого числа позиций, стремясь к $O(n)$.
3. **Атака коллизиями (Hash DoS)**: Злоумышленник может намеренно подбирать ключи, которые дают одинаковый хеш, чтобы исчерпать вычислительные ресурсы системы (перевести сложность с $O(1)$ в $O(n)$). Современные реализации (например, в Python, Rust, Java) используют рандомизированные или криптографически стойкие хеш-функции для защиты от этого.

### Резюме
| Характеристика | Средняя сложность | Худшая сложность |
| :--- | :---: | :---: |
| **Поиск** | $O(1)$ | $O(n)$ |
| **Вставка** | $O(1)$ | $O(n)$ |
| **Удаление** | $O(1)$ | $O(n)$ |
| **Память** | $O(n)$ | $O(n)$ |

**Ключ к эффективности**: Чтобы гарантировать время работы, близкое к $O(1)$, необходимо использовать качественную хеш-функцию и своевременно выполнять **рехеширование (resizing)** — увеличение размера массива и пересчет хешей всех элементов, когда коэффициент заполнения превышает определенный порог (обычно $0.75$).
