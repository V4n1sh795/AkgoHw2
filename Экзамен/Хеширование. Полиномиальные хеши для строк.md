Полиномиальное хеширование (или rolling hash) — это мощный и эффективный метод хеширования строк, который позволяет сравнивать строки и их подстроки за время $O(1)$ после предварительной обработки за $O(N)$. Он широко используется в алгоритмах поиска подстрок (например, Рабина-Карпа), проверке палиндромов и в спортивном программировании.

Ниже приведено подробное руководство по принципу работы, выбору параметров и реализации.

---

### 1. Математическая формула

Пусть у нас есть строка $S$ длины $n$, состоящая из символов. Каждый символ $S[i]$ мы представляем как его числовой код (например, ASCII-код или номер в алфавите: $a=1, b=2, \dots$).

Полиномиальный хеш строки $S$ вычисляется по формуле:
$$H(S) = \left( \sum_{i=0}^{n-1} S[i] \cdot P^i \right) \pmod M$$

где:
*   $P$ (base) — основание хеша (простое число, обычно большее размера алфавита).
*   $M$ (modulo) — модуль хеша (большое простое число).

**Пример:** Для строки `"abc"` (где $a=1, b=2, c=3$), $P=31$, $M=10^9+7$:
$H = (1 \cdot 31^0 + 2 \cdot 31^1 + 3 \cdot 31^2) \pmod M = (1 + 62 + 2883) \pmod M = 2946$.

---

### 2. Выбор параметров $P$ и $M$

Правильный выбор параметров критически важен для минимизации коллизий (ситуаций, когда разные строки имеют одинаковый хеш).

*   **Основание $P$**: Должно быть простым числом, строго большим количества уникальных символов в алфавите.
    *   Для строчных латинских букв ($26$ символов): $P = 31$ или $P = 37$.
    *   Для всех ASCII символов ($128$ или $256$): $P = 257$ или $P = 313$.
*   **Модуль $M$**: Должен быть большим простым числом, чтобы хеш-пространство было достаточно обширным.
    *   Популярные значения: $10^9+7$, $10^9+9$, $998244353$.
    *   *Важно:* Избегайте $M = 2^{64}$ (использование беззнаковых 64-битных целых чисел с естественным переполнением), так как против такого хеша существуют известные атаки (например, тесты Анти-хеш в Codeforces), генерирующие коллизии.
### 3. Префиксные хеши и хеш подстроки за $O(1)$

Главное преимущество полиномиального хеша — возможность быстро получить хеш любой подстроки $S[i \dots j]$.

Сначала мы вычисляем **префиксные хеши** $H_k$ для всех префиксов строки:
$$H_0 = S[0] \pmod M$$
$$H_k = (H_{k-1} \cdot P + S[k]) \pmod M$$

Чтобы найти хеш подстроки $S[i \dots j]$ (где $0 \le i \le j < n$), используем формулу:
$$Hash(i, j) = \left( H_j - H_{i-1} \cdot P^{j-i+1} \right) \pmod M$$
*(Если $i = 0$, то $H_{i-1}$ считается равным $0$)*.

Чтобы это работало за $O(1)$, мы заранее вычисляем и сохраняем степени $P^k \pmod M$ в отдельном массиве.
### 4. Пример реализации (Python)

```python
class PolynomialHash:
    def __init__(self, s: str, p: int = 31, m: int = 10**9 + 7):
        self.p = p
        self.m = m
        self.n = len(s)
        
        # Массив префиксных хешей
        self.h = [0] * self.n
        # Массив степеней p
        self.p_pow = [1] * self.n
        
        # Заполняем массивы
        current_hash = 0
        for i in range(self.n):
            self.p_pow[i] = (self.p_pow[i-1] * self.p) % m if i > 0 else 1
            # Преобразуем символ в число (a=1, b=2, ..., z=26)
            char_val = ord(s[i]) - ord('a') + 1
            current_hash = (current_hash * self.p + char_val) % m
            self.h[i] = current_hash

    def get_hash(self, i: int, j: int) -> int:
        """Возвращает хеш подстроки s[i...j]"""
        if i == 0:
            return self.h[j]
        
        # Формула: (H[j] - H[i-1] * P^(j-i+1)) % M
        hash_val = (self.h[j] - self.h[i-1] * self.p_pow[j - i + 1]) % self.m
        
        # В Python % всегда возвращает неотрицательное число, 
        # но в C++/Java нужно делать (hash_val % m + m) % m
        return hash_val

# Пример использования:
s = "abacaba"
ph = PolynomialHash(s)

# Хеш всей строки
print(ph.get_hash(0, 6)) 

# Сравнение подстрок "aba" (0..2) и "aba" (4..6)
print(ph.get_hash(0, 2) == ph.get_hash(4, 6))  # True
```
### 5. Борьба с коллизиями: Двойное хеширование

В задачах, где важна абсолютная надежность (или на соревнованиях, где есть тесты на взлом хеша), используется **двойное хеширование**.

Идея: вычислять хеш строки по двум разным модулям $M_1$ и $M_2$ (и, желательно, с разными основаниями $P_1$ и $P_2$). Две строки считаются равными только если совпадают **оба** хеша.

*   $P_1 = 31, M_1 = 10^9 + 7$
*   $P_2 = 37, M_2 = 10^9 + 9$

Вероятность случайной коллизии при двойном хешировании стремится к $\frac{1}{M_1 \cdot M_2} \approx 10^{-18}$, что делает его практически неуязвимым для случайных или специально сконструированных тестов.
### 6. Основные области применения

1. **Алгоритм Рабина-Карпа**: Поиск образца (паттерна) длины $m$ в тексте длины $n$ за среднее время $O(n + m)$. Мы вычисляем хеш паттерна и сравниваем его с хешем каждого окна длины $m$ в тексте, сдвигая окно за $O(1)$ благодаря свойству rolling hash.
2. **Поиск палиндромов**: Строка является палиндромом, если её хеш совпадает с хешем перевёрнутой строки. Это позволяет проверять палиндромичность любой подстроки за $O(1)$ после препроцессинга.
3. **Поиск наибольшей общей подстроки (LCS)**: В сочетании с бинарным поиском по длине ответа и хешированием можно решить задачу за $O(N \log N)$.
4. **Сравнение строк**: Быстрая проверка равенства двух строк или подстрок без посимвольного сравнения.
